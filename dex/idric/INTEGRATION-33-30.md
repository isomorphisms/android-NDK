### Final-head receipt protocol

No checkpoint above substitutes for qualification of a later commit.
Each workflow invokes `record-integration.grease` only after all required
qualification steps succeed. It copies this ledger into that run's artifact at
`dex/idric/INTEGRATION-33-30.md` and appends the literal final integration SHA,
workflow run ID, lane, observed receipts, compiler versions and artifact
identities; `INTEGRATION-33-30.sha256` binds those receipt bytes. The runtime
matrix produces one such receipt per API and stays independent of ICU/OpenSSL.

The generated ledger is the commit-bound final acceptance document. Its SHA
comes from the actual checkout and must equal the freshly generated candidate
source receipts. The final PR description records both exact workflow URLs,
their terminal conclusions and all three artifact identities after retrieval.
Workflow conclusion includes upload/service success and is read from GitHub;
the receipt assembler does not predict it. This avoids inserting a hash into
its own source commit or creating an unqualified documentation-only head.
