# One finalized layout for DEX and readable evidence

## Failure and scope

IB's retained artifact from run 38107554419 at a624cef0c1f8b867154e49c7f172f7069b4a3708 demonstrated the mismatch: its binary disassembly contained `goto/16`, but the corresponding smali still contained `goto`. The encoder had widened instructions after the evidence producer's last view of the plan. This was an evidence defect despite the separate text-probe ART success. The actual LongViewTask still failed on `Prelude.Types.fastUnpack`.

## Implementation

`finalize_file_plan` is the sole owner of method ordering, invocation/register placement and monotone goto relaxation. It returns opaque `FinalizedFilePlan`; its constructor is not exported. `Codegen` obtains that value once and supplies it to `encode_finalized_dex`, `finalized_plan` for the readable plan, and `render_finalized_smali`. The binary encoder no longer repeats placement or relaxation while encoding a finalized value. Existing byte-only and smali convenience APIs finalize their input and delegate; they are not the compiler's multiple-output path.

String evidence escapes quotes, backslashes and control characters. The checked binary encoder now writes DEX modified UTF-8 with UTF-16 lengths and string ordering, including NUL and supplementary characters. The source loop-value tests preserve literal Char, Text and bounded Boolean flags; they do not qualify general source collections or records. See `examples/autogenerated/source-loop-values/attempt.md` for the actual recovery boundary.

## Acceptance

`FinalizedLayoutCheck.idr` tests method ordering, forward/backward/cascading goto promotion, explicit goto/32, literal escaping and byte-only API equivalence. Its optional output is an encoder fixture, not source-to-DEX or ART proof.

`LayoutText.idric` separately exercises the real checked-source compiler with the IB-shaped nested text probe and requires a promoted jump. The existing arithmetic, references, effects and refusal candidates remain required.

`verify-layout.grease` compares final plan versus smali jump targets/widths/register counts; compares the literal smali jump widths with AOSP disassembly BEFORE an assembler can repair a stale report; then independently assembles the smali as an oracle and compares every method's instruction code units, local offsets, signatures and register counts. Header/file offsets may differ, but instructions may not. The candidate is always the directly emitted Idriç DEX, never the oracle.

Negative controls downgrade goto/16 in the plan, in smali, and in both reports together. The last case deliberately lets two stale reports agree and requires the actual decoded candidate to reject them. Fresh exact-head CI must pass these checks and inherited ART tests before the repair is accepted.
