# Checked exports behind platform interface callbacks

The existing checked DEX backend can now plan a stateless interface bridge.
The callback body remains an ordinary checked source export. This is the
inbound counterpart to the existing outbound framework-call surface.

```idric
%cg dex callback Landroid/view/View$OnClickListener; onClick (Landroid/view/View;)V click_action
%export "dex:click_action"
click_action : ViewReference → IO ()
```

`ViewReference` must be a concrete checked external domain whose descriptor
is established by reachable foreign declarations. The directive supplies the
interface, method, exact JVM signature and selected checked export. A missing
export, malformed descriptor, nonvoid callback or disagreement with the
checked source ABI refuses emission. Actual SDK interface conformance remains
a runtime obligation; a descriptor string is not a classpath proof.

The same generated class contains its static checked bodies, a default
Object-initializing constructor and public virtual forwarding methods. The
encoder records implemented interfaces, separates direct and virtual class
data, emits constructor access flags/invoke-direct, and counts the implicit
receiver in instance incoming registers. The receiver is never passed as the
source's first argument. Placement copies the complete incoming area when
staging is needed. Binary, plan and smali consume the same finalized value.

The old `MkMethodPlan` and `MkFilePlan` call signatures remain static defaults.
Their explicit record constructors are now `MkBoundMethodPlan` and
`MkClassFilePlan`; consumers pattern-matching the former constructors must use
the new record constructors. Existing repository callers need no changes.

There are no captured closures, instance fields, arbitrary heap values,
exception handlers, source-level object factories or automatic subtype casts.
The subsequent [Activity adapter](ACTIVITY-ADAPTERS.md) supplies a bounded
Activity lifecycle/action shape and explicit checked reference casts.
The platform owner constructs the listener and
attaches it. This generic backend owns no canonical browser state or Material
resources. Arbitrary S08 reducers/journals are not qualified by this bridge.

## Qualification inputs and limits

`examples/autogenerated/interface-callback/` contains the preceding attempt,
typed-plan controls, the actual checked source and a separate observer.
`verify-callback.grease` compiles them, executes two production-code mutants,
checks missing-export/wrong-signature source refusals, independently parses
fresh DEX and byte-compares a clean recovery build.

`verify-callback-art.grease` uses only the observed `emulator-5554` endpoint.
The observer constructs two real framework Buttons and attaches an instance
of the emitted candidate. Android's `performClick` dispatches the source body.
The candidate receives the actual clicked view and preserves exact incoming
Unicode/whitespace text. A changed identity condition must fail the same
observer with status 73. Candidate and separately assembled observer bytes
are pulled back and compared before each execution.

The fixture transports Text through `View.transitionName`. It does **not**
draw Material 3 text, resolve an MDC dependency closure, package resources or
an APK, exercise touch/accessibility or establish physical-device behavior.
It is an input/compiler boundary qualification, not a replacement IB view.
The existing workflow retains its separately named inherited bootstrap debt;
these observations cannot confer shared build-policy or merge acceptance.

At the first publication the compatibility backend source check passed with
the pinned core's inherited stage-one bootstrap executable
`0.8.0-1b5176dc9`; the rebuilt `ff4d85286` checker and hosted source/runtime
results were still pending. The scripts parsed with the preserved Grease fork
at Oils `5651cf97a1b5042f24f14112a7ade9a1518eb0bc`, executable SHA-256
`7e31cd05b7a9d8fb2a4a9e003a7f3fcb0159138506d17f0fb28da8cbe22aa85c`.
Its documented implementation entry is used inside the Grease/Oils boundary;
CI uses the existing consumer-facing Grease entry at its own pinned source.
Parse checks alone are not execution receipts. Current results belong in the
review PR and retained run artifact.
