# Checked native construction and Activity lifecycle

This continues the platform boundary from
[isomorphisms/android-NDK PR #25, “Generate interface callbacks that forward to checked Idriç exports”](https://github.com/isomorphisms/android-NDK/pull/25),
at `b7a637fdbf3e3725c8113bf665333215d569ceb2`. Application behavior and resources
remain owned by IB; this backend change supplies construction, register placement
and the bounded Activity bridge.

`dex:construct:OWNER:<init>:(ARGUMENTS)V` admits an effectful opaque source
result for the newly initialized owner. It excludes the allocated receiver from
source arguments and emits new-instance followed by invoke-direct, without a
move-result after the void constructor. Type indices use the actual type pool.
High destinations are allocated through a low scratch reference and moved as
objects before their constructor invocation. The initial test caught an actual
placement gap when an invocation already qualified for /range; that production
gap was fixed without weakening the oracle.

The bounded class directives admit Activity and onCreate(Bundle). The generated
constructor calls the Activity parent, and onCreate invokes the platform parent
with the original receiver and Bundle before invoking the checked static handler.
The source handler may use both values or just its Activity receiver. Unsupported
parents/lifecycles, missing/mismatched exports and repeated declarations refuse.
