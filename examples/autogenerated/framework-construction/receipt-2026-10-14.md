# Checked native construction and Activity lifecycle

This continues the platform boundary from
[isomorphisms/android-NDK PR #25, “Generate interface callbacks that forward to checked Idriç exports”](https://github.com/isomorphisms/android-NDK/pull/25),
at `b7a637fdbf3e3725c8113bf665333215d569ceb2`. Application behavior and resources
remain owned by IB; this backend change supplies construction, register placement
and the bounded Activity bridge.

`dex:construct:OWNER:<init>:(ARGUMENTS)V` admits an effectful opaque source
result for the newly initialized owner. It excludes the allocated receiver from
source arguments and emits new-instance followed by invoke-direct, without a
move-result after the void constructor. Type indices use the actual type pool.
High destinations are allocated through a low scratch reference and moved as
objects before their constructor invocation. The initial test caught an actual
placement gap when an invocation already qualified for /range; that production
gap was fixed without weakening the oracle.

The bounded class directives admit Activity and onCreate(Bundle). The generated
constructor calls the Activity parent, and onCreate invokes the platform parent
with the original receiver and Bundle before invoking the checked static handler.
The source handler may use both values or just its Activity receiver. Unsupported
parents/lifecycles, missing/mismatched exports and repeated declarations refuse.

## Runtime history and required gate

Local Android14/SDK34/x86_64 software-emulator runs initially exited137. Logcat
revealed observer initialization failures, not a constructor failure: selection's
DeviceConfig lookup used a system Application package while the process UID was
shell; creating a shell view Context alone did not change the current Application.
A subsequent observer attempt additionally exposed the lazy font map that normal
application binding initializes. Those failures are retained as failures.

The independent observer now loads Android's actual preinstalled font map and
uses the framework app-context initializer with the actual shell LoadedApk.
Android's createPackageContext copies its container's app-ops identity, so that
copy alone retained the wrong system attribution. The observer now checks its
app-ops package explicitly and attaches that context to its initial Application.
Provider permissions
still use the real shell UID; no candidate behavior, framework result or selection
configuration is replaced. Runtime acceptance remains separate until original
and recovery exit0 with the complete marker after received-byte comparisons.
The extended existing workflow runs this gate alongside the inherited ART tests
on its SDK34/x86_64 emulator. Local runtime acceptance is PENDING at this receipt.

## Packaging boundary

The bounded direct-DEX Activity candidate packager accepts an explicit existing
public-test keystore, application manifest/resources/package and checked DEX.
Its positive IB build checks resource linkage, DEX byte identity, certificate,
alignment and launcher. Wrong certificate, missing signer and wrong package all
exit1 with their intended diagnostics and expose no final APK.

This does not supply independent AICI promotion, central IB package registration,
production/private signing, versioned upgrade compatibility or physical-device
acceptance. The PR remains draft and unmerged; arbitrary subclass support and
browser/source/store semantics are not claimed.
